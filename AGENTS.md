\# AGENTS.md\# Agent Operating Instructions\## PurposeThis file defines how AI coding agents must work inside this repository.The project is a local-first desktop application for managing the Project Mina-Ale 16-step audiovisual production workflow.Agents must treat this repository as a production system, not as a prototype playground.The app coordinates structured Google Docs prompt templates, local workflow state, human creative checkpoints, versioned outputs, and Google Drive synchronization.\---\## Product SummaryThe application is a local-first creative production workflow system.It must help the user move through a 16-step AI-assisted video production process:```text01 — Research Brief Builder02 — Angle \\\\\\\& Thesis Generator03 — Angle Evaluator04 — Script Blueprint Builder05 — Script Version Generator06 — Multi-Agent Script Evaluator07 — Master Cut Builder08 — Layered Rewrite \\\\\\\& Final Polish09 — Visual Layer Builder10 — Voice Production Plan11 — AI Narration Generation12 — Audio Cleanup \\\\\\\& Podcast Master13 — Asset Sourcing \\\\\\\& Rights Check14 — Long-Form Video Assembly15 — Derivatives Package16 — Final QA, Export \\\\\\\& Publish````The app must not behave like a generic chatbot.It must behave like a controlled workflow engine.\---\## Core Design PrincipleNever bypass human creative approval.Every meaningful AI-generated output must stop in a human review state before it can become an approved dependency for the next step.The user must always be able to:\* inspect the rendered prompt before execution;\* review the generated output;\* approve the output;\* reject the output;\* regenerate the output;\* add creative feedback;\* manually edit or replace the output;\* compare output versions;\* lock an approved version.\---\## Local-First RuleThe local application is the primary working environment.SQLite and local snapshots are the source of truth for workflow state.Google Drive is a sync target and document repository, not the only source of truth.Agents must not design features that require cloud deployment.The app must run locally.Allowed app styles:\* Tauri + React + TypeScript + SQLite\* Local-only development server during development\* Local filesystem snapshots\* Google Drive and Docs API integrationNot allowed as a core requirement:\* mandatory hosted backend;\* mandatory public web deployment;\* mandatory SaaS database;\* cloud-only state;\* server-only workflow engine.\---\## Preferred Technical StackUse this stack unless explicitly changed by the human owner:```textDesktop shell: TauriFrontend: ReactLanguage: TypeScriptStyling: Tailwind CSSLocal database: SQLiteBackend runtime: Rust through Tauri commandsPrompt/output snapshots: local filesystemRemote document mirror: Google Drive / Google DocsAI providers: OpenAI and/or Gemini through provider abstraction```Manual paste mode must also exist.Manual paste mode means:1\. The app renders the final prompt.2\. The user copies it into an external AI tool.3\. The user pastes the AI output back into the app.4\. The app tracks the output as a normal workflow artifact.This protects the workflow if API automation is unavailable.\---\## Repository StructureAgents should preserve this Its required prompt template exists.2\. Its required variables are resolved.3\. Its upstream dependencies are approved.4\. Its human-required fields are filled.5\. Its output location is known.6\. Its execution mode is selected.A workflow step must never become a dependency unless it is approved or manually marked as accepted by the user.\---\## Required Workflow StatesUse these workflow states unless the architecture document later refines them:```textnot\\\\\\\_startedblockedreadyinput\\\\\\\_missinginput\\\\\\\_readyrunningoutput\\\\\\\_generatedawaiting\\\\\\\_human\\\\\\\_reviewapprovedrejectedregeneration\\\\\\\_requestedsupersededlockedfailedsync\\\\\\\_pendingsyncedsync\\\\\\\_conflict```Agents must not invent incompatible states without updating the state machine document.\---\## Prompt Template RulesPrompt templates are structured contracts.They are not plain blobs of text.Agents must preserve support for:\* prompt number;\* prompt title;\* prompt source Google Doc ID;\* template version;\* placeholder extraction;\* placeholder-to-variable mapping;\* required inputs;\* optional inputs;\* upstream dependencies;\* output artifact type;\* human review requirement;\* regeneration rules.The app must detect unresolved placeholders before execution.Example placeholders:```text\\\\\\\[PASTE RESEARCH BRIEF HERE]\\\\\\\[PASTE FINAL POLISHED SCRIPT HERE]\\\\\\\[INSERT LANGUAGE AND REGION]\\\\\\\[PASTE VOICE PRODUCTION PLAN HERE]\\\\\\\[PASTE FINAL METADATA HERE]\\\\\\\[INSERT HUMAN DECISIONS HERE]```Agents must not hardcode only one prompt.All 16 workflow steps must be represented in the prompt registry.\---\## Output Artifact RulesEvery generated output must be treated as a versioned artifact.An artifact must have:\* artifact ID;\* episode ID;\* workflow step number;\* artifact type;\* version number;\* local snapshot path;\* optional Google Doc ID;\* created timestamp;\* model/provider metadata if generated by AI;\* human approval state;\* dependency references.Outputs must never overwrite previous approved versions.New generations create new versions.\---\## Naming ConventionUse clear file naming.Recommended local snapshot names:```textEP01\\\\\\\_S01\\\\\\\_ResearchBrief\\\\\\\_v001.mdEP01\\\\\\\_S02\\\\\\\_AngleList\\\\\\\_v001.mdEP01\\\\\\\_S03\\\\\\\_AngleDecision\\\\\\\_v001.mdEP01\\\\\\\_S04\\\\\\\_Blueprint\\\\\\\_v001.mdEP01\\\\\\\_S05\\\\\\\_ScriptVersions\\\\\\\_v001.mdEP01\\\\\\\_S06\\\\\\\_ScriptEvaluation\\\\\\\_v001.mdEP01\\\\\\\_S07\\\\\\\_MasterCut\\\\\\\_v001.mdEP01\\\\\\\_S08\\\\\\\_FinalScript\\\\\\\_v001.mdEP01\\\\\\\_S09\\\\\\\_VisualPlan\\\\\\\_v001.mdEP01\\\\\\\_S10\\\\\\\_VoicePlan\\\\\\\_v001.mdEP01\\\\\\\_S11\\\\\\\_NarrationGen\\\\\\\_v001.mdEP01\\\\\\\_S12\\\\\\\_AudioMasterPlan\\\\\\\_v001.mdEP01\\\\\\\_S13\\\\\\\_AssetRights\\\\\\\_v001.mdEP01\\\\\\\_S14\\\\\\\_LongformAssembly\\\\\\\_v001.mdEP01\\\\\\\_S15\\\\\\\_Derivatives\\\\\\\_v001.mdEP01\\\\\\\_S16\\\\\\\_QAPublish\\\\\\\_v001.md```\---\## UI PrincipleThe interface should be inspired by DaVinci Resolve’s page-based workflow.Use a persistent bottom navigation bar with 16 workflow icons.Each icon opens a dedicated workspace.The user must always understand:\* where they are in the workflow;\* which step is active;\* what the step requires;\* what output was generated;\* whether the output is approved;\* whether the step is synced to Drive;\* what action is allowed next.\---\## UI ModulesThe bottom navigation modules are:```text01 Research02 Angles03 Evaluate04 Blueprint05 Drafts06 Board07 Master08 Polish09 Visuals10 Voice11 Narration12 Audio13 Assets14 Assembly15 Derivatives16 Publish```Each module should expose the same core layout:```textLeft panel: inputs, sources, variablesCenter panel: rendered prompt, output, document view, diffRight panel: status, checklist, actions, sync stateBottom bar: 16-step navigation```\---\## Human Review ConsoleAgents must prioritize the human review console.The review console must support:\* output reading;\* rendered prompt reading;\* version comparison;\* approve;\* reject;\* regenerate;\* add feedback;\* edit manually;\* lock version;\* mark as superseded;\* return to previous step.The app must make approval explicit.No implicit approval.\---\## Google Drive RulesGoogle Drive integration must be cautious and reversible.Agents must implement or preserve:\* OAuth through external browser;\* least-privilege scopes where possible;\* local token storage through secure storage when available;\* Drive folder selection;\* prompt template import;\* Google Doc output creation;\* sync status;\* sync conflict detection;\* dry-run mode before destructive operations.Do not delete Drive files in MVP.Do not rename or move remote files without explicit user confirmation.Do not assume Drive is always online.\---\## Google Docs RulesGoogle Docs is used for human-readable prompt templates and output documents.Agents must support:\* reading Google Docs prompt templates;\* extracting raw text;\* caching template content locally;\* detecting remote changes;\* creating output Google Docs;\* writing generated outputs;\* linking local artifact versions to remote docs.Google Docs should not be used as the only database.\---\## SQLite RulesSQLite is the local source of truth.Agents must design SQLite tables for:\* projects;\* channels;\* episodes;\* workflow step definitions;\* workflow step runs;\* prompt templates;\* prompt template versions;\* variables;\* artifacts;\* artifact versions;\* human reviews;\* drive links;\* sync events;\* audit events;\* app settings.SQLite must use:```sqlPRAGMA foreign\\\\\\\_keys = ON;PRAGMA journal\\\\\\\_mode = WAL;```Migrations must be versioned.\---\## Security RulesNever commit secrets.Never hardcode API keys.Never store OAuth refresh tokens in plain text if secure storage is available.Never log full access tokens.Never expose the full contents of private Google Drive documents in debug logs.Use `.env.local` or local secure configuration for secrets.The app must work in manual mode without API keys.\---\## AI Provider RulesThe AI provider layer must be abstract.Do not bind the workflow engine directly to a single provider.Supported modes:```textmanual\\\\\\\_pasteopenai\\\\\\\_apigemini\\\\\\\_api```The workflow engine should call an internal provider interface, not raw provider SDKs.Provider metadata must be saved with each generated artifact:\* provider;\* model;\* timestamp;\* temperature if available;\* input hash;\* output hash;\* token/cost estimate if available.\---\## Regeneration RulesRegeneration must create a new version.It must never overwrite the previous version.Regeneration should allow:\* same prompt, same variables;\* same prompt, new human feedback;\* edited variables;\* changed model;\* changed creative constraints;\* manual paste replacement.Regeneration should mark previous versions as:```textsupersededrejectedalternativeapprovedlocked```depending on user action.\---\## Error Handling RulesErrors must be human-readable and recoverable.Do not fail silently.Every error should explain:\* what failed;\* where it failed;\* whether local data is safe;\* whether remote sync was affected;\* what action the user can take next.Critical actions must use dry-run or confirmation.\---\## Testing RulesAgents must add or update tests for:\* prompt placeholder parsing;\* prompt rendering;\* unresolved placeholder detection;\* workflow state transitions;\* dependency blocking;\* approval gating;\* artifact version creation;\* local snapshot creation;\* Drive sync dry-run;\* Google Docs output writer mock;\* UI navigation between 16 steps.Do not ship workflow changes without tests.\---\## MVP BoundaryThe MVP should implement:1\. Local app shell.2\. SQLite persistence.3\. Prompt registry for 16 steps.4\. Manual prompt execution mode.5\. Google Drive prompt import.6\. Google Docs output mirror.7\. Episode creation.8\. Workflow states.9\. Human review console.10\. Versioned artifacts.11\. Bottom navigation with 16 modules.12\. Step 01–04 or Step 01–05 fully functional.Do not attempt full media automation in the MVP.\---\## Non-GoalsDo not build these unless explicitly requested:\* video editing automation;\* direct DaVinci Resolve control;\* direct YouTube publishing;\* direct podcast publishing;\* full collaborative multi-user editing;\* cloud backend;\* real-time sync between multiple machines;\* advanced analytics;\* semantic search across all outputs;\* full rights-management legal system.\---\## Agent Working StyleWhen modifying code:1\. Read the relevant docs first.2\. Identify the bounded context.3\. Make the smallest coherent change.4\. Preserve existing contracts.5\. Add tests.6\. Update docs only if behavior changes.7\. Avoid broad rewrites.8\. Keep UI and workflow terminology consistent.9\. Do not invent new concepts when existing ones are sufficient.10\. Prefer explicit state and typed contracts.\---\## Required Skill FilesAgents should consult the relevant skill document before working in a domain:```textagents/skills/drive-sync.mdagents/skills/prompt-contracts.mdagents/skills/workflow-engine.mdagents/skills/ui-shell.mdagents/skills/security-qa.md```\---\## Definition of DoneA change is done only when:\* it preserves local-first behavior;\* it does not bypass human review;\* it respects the 16-step workflow;\* it does not overwrite approved outputs;\* it has tests or a clear manual test case;\* it does not expose secrets;\* it documents any changed contract;\* it works in manual mode or degrades gracefully without APIs.\---\## Final Product StandardThe app should feel like a professional creative production console.It should combine:\* the page-based clarity of DaVinci Resolve;\* the editorial rigor of a script development room;\* the traceability of a production management system;\* the flexibility of AI-assisted generation;\* the safety of local-first ownership.The goal is not maximum automation.The goal is controlled creative acceleration.``````
